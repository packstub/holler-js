# Changelog

All notable changes to `@packstub/calls` are documented in this file.

## Unreleased

First release. The engine moved here from `packstub/filament-calls` (its `js/` folder), unchanged.

- `CallClient`: media and `RTCPeerConnection` with perfect negotiation (the callee polite), ordered ICE candidates, screen share by track replacement (a video track is added on a voice call), voice fallback when there is no camera, mute and camera off, a `reconnecting` state and a drop timeout, `resumes` for a window that leaves calls to a pop-out.
- Reconnecting after a page load: each window has a `tab` id and holds its side of a call through the poll; `leave()` frees it as the page unloads; a fresh page claims the side, sends `reset` and a new offer; signals carry a `session` id so leftovers from an old connection are ignored.
- `HttpSignaling`: the polling adapter over JSON routes (`__ID__` placeholder), extra headers for CSRF, a `leave` beacon with form fields.
- `state` signal and `peerstate` event: a side tells the other when it mutes, turns the camera off or shares the screen (`peerMuted`, `peerCameraOff`, `peerSharing`); what is on is announced again to a side that joins or comes back from a reload, and a side that resets its connection starts with everything off.
- `takeOver()`: a tab in the `elsewhere` state (its pop-out ran the call) continues the call itself once no window holds it, back to ringing when the pop-out closed before answering; a pop-out that is only reloading keeps its side, since the server's claim decides.
- A Vitest suite with fake WebRTC globals and an in-memory signaling server.
- Group calls ([#1](https://github.com/packstub/calls-js/issues/1)): `callUser()` takes a list of people, `invite()` adds one to a running call, also from a tab whose pop-out runs it (`canInvite()`, a `maxParticipants` option, 4 by default; the server keeps the hard limit). The client keeps a roster (`peers`, with `peers`, `peerjoined` and `peerleft` events; `remotestream` and `peerstate` say which peer they are about) from the call's `peers`, each with a `seat`: between two participants the lower seat offers, so a 1-on-1 call behaves as before. Someone who hangs up leaves the call for the others; a page that reloads resets each peer separately, and a call stays `active` while media flows from at least one peer.
- `MeshTopology`, the default `topology`: one `RTCPeerConnection` per peer, perfect negotiation per pair. The `topology` option takes an instance, a class or a factory per call, with a small interface (`connect`, `disconnect`, `signal`, `connected`, `leave`, and optional `join`, `reset`, `stale`, `replaceVideo`) for an SFU or a relay in bigger rooms.
- Signaling: `start(callees, tab)` with one id or an array (`HttpSignaling` posts `callee` or `callees`), `send(callId, type, payload, to)` addressed to one participant or to all, signals carry `from`, an optional `invite(callId, userId)` (route `invite`); the call shape gains `peers`, `seat` and `joined`. A 1-on-1 backend that sends none of this keeps working: the client derives the one peer, the seats and the sender.
- The in-memory test server knows participants, seats, addressed signals and invites; `participant(callId, userId)` exposes a person's record, `withdraw(call, participant, status)` marks someone missed or dropped the way the Laravel server's expiry does.
- `CallWidget` (`@packstub/calls/widget`, with `widget.css`): the call UI for any page without a framework, the same the Filament widget draws: incoming toast, call window with a tile per participant, your own picture, mute, camera, screen share (a shared screen takes the stage, the cameras in a strip on top or on the right), hang up, the chip while a pop-out runs the call, notices, the ring tones, the pop-out flow (`windowUrl`, `popup`). `data-calls-call` elements ring people; `calls:<type>` events on the page; `labels`, `icons` and the five view `templates` (kept current through `data-calls-*` hooks) are overridable, and the class is made to be subclassed. Tested under jsdom.
- A window that rings for a call the server gave up on (the invitee was marked missed, or declined on another device, while the call goes on for the others) stops ringing and ends as `missed`, instead of ringing until someone clicks.
- An `answer` names the offer it answers: a page that offered to someone still ringing, reloaded and offered again ignores the answer to its first offer, which used to take the new connection's place.
- Data channels and calls without media: `channels` opens ordered data channels to every peer (from the side that offers, again after a reload; `datachannel` event, `client.channel()`), `media: 'none'` connects without the camera or the microphone, `startMedia('audio' | 'video')` adds them mid-call on every connection (a microphone going to video is replaced, not doubled), `drain(channel)` waits while a channel's buffer is full. `iceTransportPolicy` (`relay`) on every connection.
- ICE servers per call: `iceServers` may be a function, or `'signaling'` to ask `HttpSignaling.configuration()` (route `ice`) each time a call starts, so short-lived TURN credentials never go stale in a long-lived page.
- `kind`: `HttpSignaling({ kind })` and `poll({ kind })` ask only for calls of that kind; the widget polls for `call`, so another package's calls (Session Replay's assist) never ring in it. The call shape gains `kind`.
- Errors carry `reason` from the server (`busy`, `not_ringing`…): a callee on another call ends the attempt as `ended { reason: 'busy', call: null }` instead of an error, a call that stopped ringing as you answered ends as `missed`. `HttpSignaling` gives up a request after `timeout` (10 s).
- A poll sent before a hang-up or a decline is no longer applied after it (the call rang again, or a group call was resumed); a double click on Accept or on a call button asks for the camera once and answers or rings once; a window joining another call closes the old connections; a screen picked after the call ended is stopped at once.
- The camera prompt no longer stops the heartbeat: answering and resuming run beside the polls, which hold the side meanwhile, so the main tab never takes a call back from a pop-out whose prompt is open.
- Both pages of a call reloading at once connect again: the lower seat keeps offering (once more if the other page missed it), the higher seat gives way.
- A hidden tab with no call polls every `poll.hidden` ms (15 s), and at once when shown. `client.destroy()` lets go of the call and closes everything without events.
- Widget: a pop-out link alone no longer rings anyone or answers a call (a one-time token the opening page leaves in `localStorage`); `destroy()` takes the call down and closes the ring's audio context; 401 and 419 stop polling quietly, a server error shows nothing raw; the chip's clock counts from the answer; `calls:sharing` fires only when a screen starts or stops; a `$` in a name stays as it is. Options renamed before 1.0: `popup` → `inPopOut`, `autoStart` → `openedFor`, `autostart` → `startPolling`.
- Someone invited again at a new seat after leaving is a fresh peer even when this window never saw them leave: their old connection is closed and the new seat decides who offers.
